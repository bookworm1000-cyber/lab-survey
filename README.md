# 研究室事前調査(電気電子情報工学科)

研究室配属の希望順位と通算GPAを匿名で集め、各研究室の第1希望者のなかで自分が何位かを人型の図で確かめられるアンケートです。画面は GitHub Pages、データの保存は Google スプレッドシート(Apps Script)で動きます。名前や学籍番号は扱いません。

## できること

- URL を開けばすぐ回答を始められる。送信すると「回答コード」(英数字10文字)が発行され、その端末に保存される
- 回答コードがあれば、別の端末からでも回答の修正と結果の閲覧ができる
- 通算GPA を数字で入力すると、7 セグメント表示のメーターに反映される
- 研究室を第1希望から順にタップして希望順位を作る(3つ以上で送信可、並べ替え・削除可)
- 送信した人だけが結果を見られる
  - 第1希望の研究室について、第1希望者を GPA 順に並べた人型の図と「あなた」の矢印、順位、判定(定員内・GPA枠内・ボーダー・選考枠)
  - 学科全体の GPA 分布を使った「学年全員が回答したと仮定した場合」の推定順位と人数
  - 配属の見込み:配属の手順を 400 回シミュレーションし、第1希望・第2希望…のそれぞれに決まる割合を表示
  - 全研究室の第1希望者数(回答者の実数と推定)と定員の比較
  - 回答者と学科全体の GPA 分布の比較、学年全体での推定順位
- 結果画面のスクリーンショット対策(下の「スクリーンショット対策について」を参照)

## ファイル構成

| パス | 内容 |
|---|---|
| `index.html` | ページ本体 |
| `css/style.css` | 見た目 |
| `js/config.js` | **サーバーの URL、学年の人数と GPA 分布を書く場所** |
| `js/labs.js` | 研究室・教員・定員の一覧 |
| `js/app.js` | 画面と集計 |
| `js/guard.js` | スクリーンショット対策 |
| `js/demo.js` | サーバー未設定時のデモ用データ |
| `gas/Code.gs` | Apps Script に貼るサーバー側のコード |

`js/config.js` の `API_URL` が空のままだとデモモードで動きます(架空の回答 64 件 + そのブラウザで入力した回答)。見た目の確認はこの状態でできます。

## 公開手順

### 1. データの保存先(Google スプレッドシート + Apps Script)

1. Google ドライブで新しいスプレッドシートを作る(名前は自由)
2. メニューの「拡張機能」→「Apps Script」を開く
3. 最初からある `コード.gs` の中身をすべて消し、`gas/Code.gs` の中身を貼り付けて保存する
4. 上部の関数選択で `setup` を選び「実行」。権限の確認が出たら自分のアカウントで許可する
   (「このアプリは Google で確認されていません」と出たら「詳細」→「(プロジェクト名)に移動」)。
   実行ログに「準備ができました。」と出て、スプレッドシートに `responses` シートができれば成功
5. 右上の「デプロイ」→「新しいデプロイ」→ 種類の歯車から「ウェブアプリ」を選び、次のように設定して「デプロイ」
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
6. 表示された「ウェブアプリの URL」(`https://script.google.com/macros/s/…/exec`)をコピーする

`setup` は保存先スプレッドシートの ID をスクリプト プロパティ `SHEET_ID` に記録します。ウェブアプリとして動くときは「つながっているスプレッドシート」を取得できないため、この ID で開きます。

スプレッドシートの「拡張機能」からではなく Apps Script のホーム画面などで単独のスクリプトを作った場合は、`setup` の前に「プロジェクトの設定」→「スクリプト プロパティ」で `SHEET_ID` に保存先スプレッドシートの ID(URL の `/d/` と `/edit` の間の文字列)を追加してください。

### 2. 画面(GitHub Pages)

1. `js/config.js` の `API_URL: ''` の `''` の中に、手順 1-6 の URL を貼る
2. このフォルダの中身を GitHub のリポジトリに置く(GitHub Pages を無料で使うにはリポジトリを public にする)
3. リポジトリの「Settings」→「Pages」→ Branch を `main`、フォルダを `/ (root)` にして保存
4. 1〜2 分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けるようになる

### 3. クラスへの共有

`https://<ユーザー名>.github.io/<リポジトリ名>/` をそのまま共有します。合言葉はないので、URL を知っている人は誰でも回答できます。結果を見られるのは回答した人だけです。

## 運用

- **回答を見る**: スプレッドシートの `responses` シート。回答コードはハッシュ値で記録され、誰の回答かは管理者にも分かりません
- **Code.gs を直したとき**: 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョンを「新バージョン」にして「デプロイ」。URL は変わりません(「新しいデプロイ」を作ると URL が変わるので `config.js` も直す必要があります)
- **受付を締め切る**: 「デプロイを管理」からデプロイをアーカイブする(結果も見られなくなる)
- **回答コードをなくした人**: 管理者にも本人の行は分からないので、元の回答は消せません。新しく回答し直すと二重に数えられるため、なくさないよう案内してください(同じ端末なら自動で入れます)
- **二重回答について**: 学籍番号を使わないため、別の端末やブラウザから何度も回答することは技術的には防げません。URL を知っていればクラス外の人も回答できるので、「1人1回」「URL はクラス内だけで共有」のお願いベースになります
- **研究室や定員を変える**: `js/labs.js` を編集する。`id` は保存データに使われているので、回答が集まり始めてからは変えないでください
- **最小希望数を変える**: `js/config.js` の `MIN_CHOICES` と `gas/Code.gs` の `MIN_CHOICES` の両方を変える

## 判定と推定の前提

配属は次の手順で決まる前提で計算しています。実際のルールと違う部分があれば `js/app.js` の `judge`(第1希望の判定)と `simulate`(配属の見込み)を調整してください。

1. 各研究室の定員のうち半分(切り捨て)を、第1希望者のなかから GPA の高い順に確定する。定員が「6〜8」なら GPA枠は 3〜4 席
2. 残りの枠(選考枠)は志望理由書などで選考される
3. 第1希望で決まらなかった人は、GPA の高い人から順に、まだ空きのある研究室のうち希望順位がいちばん高いところに決まる

第1希望の人型の図は 1〜2 の段階での位置です。第1希望者が定員の下限以下なら「定員内」と表示します。研究室ごとの表で研究室をタップすると、そこを第1希望にした場合の位置が出ます。

「配属の見込み」は 1〜3 を 400 回くり返した割合です。毎回、定員を目安の範囲からランダムに決め、選考枠の合格者は第1希望者のなかからくじ引きで選びます(志望理由書の評価は予測できないため)。回答者が学年の 9 割に満たないうちは、回答者を下の重みで復元抽出して 170 人分の仮想の学年を作って計算します。他の人の回答が 9 件未満のあいだは計算しません。

「学年全員が回答したと仮定すると」の推定は、`js/config.js` の `COHORT`(学年の人数 170 人と、学科の通算GPA分布)を使います。

- 学年全体での順位: 学科の分布で自分より GPA が高い人の割合 × 170 人。0.5 刻みの階級の中では均等に散らばっていると仮定
- 研究室ごとの推定人数・推定順位: 回答者一人ひとりに「その GPA 帯の学科全体の人数 ÷ その GPA 帯の回答者数」の重みを付けて足し合わせる。GPA の高い人ほど回答しやすい、といった偏りを補正するため。まだ回答していない人も、同じ GPA 帯の回答者と同じ傾向で志望すると仮定している
- 回答者が学年の 9 割を超えたら推定は表示しない

分布の出典(2024年度入学生の通算GPA分布、学科平均 2.41)が新しくなったら `COHORT.pct` を差し替えてください。

## スクリーンショット対策について

ウェブページから OS のスクリーンショット機能そのものを止める方法はありません。動画配信サービスで画面録画が真っ黒になるのは DRM(Widevine・FairPlay)で暗号化された動画だけに効く仕組みで、使うには有料の DRM ライセンスサーバー、結果画面を動画に変換して暗号化するサーバー、iPhone 向けには Apple の審査が必要になるため、この構成では採用していません。

代わりに、1回の撮影で持ち出せる情報を小さくする対策を組み合わせています。

- **押している間だけ表示**: 他の人の GPA や人数が入った部分(第1希望の人型の図、研究室ごとの棒、GPA分布)はふだん隠れていて、スマホでは指で押している間だけ、PC ではカーソルを合わせている間だけ、その1枚分だけが見える。指を滑らせると隣の行に切り替わる。スマホでスクショを撮るには、画面を押したままもう一方の手で本体のボタンを押す必要があり、撮れても1枚分だけになる(`config.js` の `HOLD_TO_REVEAL: false` で無効にできる)
- ウィンドウからフォーカスが外れたとき、タブやアプリを切り替えたときに画面をぼかす
- Windows キー / ⌘ キー(Win+Shift+S、⌘+Shift+4 などの起点)や PrintScreen キーが押された瞬間に画面をぼかし、PrintScreen 後はクリップボードを上書きする
- 印刷・保存のショートカット、右クリック、文字の選択とコピーを無効にする
- 結果画面全体に、閲覧ID(回答コードから作った短い記号)と日時、「転載禁止」の透かしを薄く重ねる

自分の順位や判定、配属の見込みなど、本人に関する結論は押さなくても見えます。
